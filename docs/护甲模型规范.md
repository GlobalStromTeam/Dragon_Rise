# 护甲模型规范（1.21.1 / SimpleBedrockModel v2）

> 一句话：**armor 骨的 pivot 必须精确等于下表的值，且与其 biped 父骨一致**；立方体用模型空间绝对坐标；贴图像素是声明的整数倍；`uv_rotation` 必须为 0。
> 违反第一条的实际后果：整件护甲位移（本项目踩过的坑是 8 件胸甲的 `armorBody` 写成 22，导致"胸甲飞到头上"）。

---

## 1. 为什么会有这份规范

| 版本 | 渲染路径 | pivot 语义 |
|---|---|---|
| 1.20.1 | GeckoLib `GeoArmorRenderer` | 每帧用原版部件位置**覆盖** armor 骨位置 → geo 里 pivot 写成什么都无所谓 |
| 1.21.1 | SBM v2 `GeoArmorRendererV2` + `TreeArmorModelInstance.preparePose` | 在烘焙出的 **bind** 上**累加** `(原版部件位置 − 静息偏移)`；cube 顶点按骨骼**绝对 pivot** 烘焙 → **pivot 错 = 整件位移** |

所以迁移时把 GeckoLib 时代"随便写"的 pivot 原样搬过来，就出现了胸甲上浮。
校验/修复工具：`tools/armor_geo_norm.mjs`（见第 6 节）。

---

## 2. 目录与命名

```
assets/dragonrise_reforge/models/bedrock/armor/<name>.geo.json    ← 模型
assets/dragonrise_reforge/textures/armor/<name>.png               ← 贴图
```

- 文件名全小写、下划线分隔；贴图名 = 模型名去掉 `_helmet / _chest / _pants / _leggings` 后缀。
- 物品类里用两个常量指向它们，渲染器统一走 `SbmArmorRenderer`：

```java
public static final ResourceLocation GEO = ResourceLocation.fromNamespaceAndPath("dragonrise_reforge", "models/bedrock/armor/jungle07_chest.geo.json");
public static final ResourceLocation TEXTURE = ResourceLocation.fromNamespaceAndPath("dragonrise_reforge", "textures/armor/jungle07.png");
```

## 3. 必需骨骼与 pivot（硬约束）

| 骨骼 | parent | pivot | 备注 |
|---|---|---|---|
| `bipedHead` | —（root） | `[0, 24, 0]` | 头盔族的父骨 |
| `armorHead` | `bipedHead` | `[0, 24, 0]` | |
| `bipedBody` | —（root） | `[0, 24, 0]` | 胸甲族的父骨 |
| `armorBody` | `bipedBody` | `[0, 24, 0]` | **最容易写错成 22** |
| `bipedRightArm` | —（root） | `[-5, 22, 0]` | |
| `armorRightArm` | `bipedRightArm` | `[-5, 22, 0]` | |
| `bipedLeftArm` | —（root） | `[5, 22, 0]` | **最容易写成 -5**（左右符号） |
| `armorLeftArm` | `bipedLeftArm` | `[5, 22, 0]` | |
| `bipedRightLeg` | —（root） | `[-2, 12, 0]` | |
| `armorRightLeg` | `bipedRightLeg` | `[-2, 12, 0]` | |
| `armorRightBoot` | `bipedRightLeg` | `[-2, 12, 0]` | 靴子挂腿骨下 |
| `bipedLeftLeg` | —（root） | `[2, 12, 0]` | |
| `armorLeftLeg` | `bipedLeftLeg` | `[2, 12, 0]` | |
| `armorLeftBoot` | `bipedLeftLeg` | `[2, 12, 0]` | |

规则：

1. **`armor*` 与其 biped 父骨 pivot 完全一致**（bind = 0）——这是本次修好胸甲的那条。
2. biped 骨只允许臂/腿在 `|x|` 上做 ≤1 格的厚度微调，`y` 必须是 24 / 22 / 12，`z` 必须是 0。
3. 左右符号保持一致（右 = 负、左 = 正），整份模型不要混用。
4. 骨骼名唯一；`parent` 必须真实存在（不要留指向已删骨骼的悬空 parent）。
5. 只需含本族需要的骨骼：头盔 `bipedHead + armorHead`，胸甲再加双臂，护腿再加双腿与 boots。

---

## 4. 立方体（cube）坐标

- 用**模型空间绝对值**：原点在脚底、`+y` 向上，`16` 单位 = 1 格。
- **不要写相对 pivot 的坐标**。躯干正常范围 `y≈12..24`，头 `24..32`；超出部分只应是背包/天线等附件。
- 所有 cube 都挂在对应 armor 骨或它的子骨上即可（子骨的 pivot 也建议与其父一致）。

---

## 5. 贴图

- geo 的 `description.texture_width/height` 填"素材逻辑尺寸"，**PNG 实际像素必须是它的整数倍**（本项目多数是 2×）。
- 非整数倍会让 UV 采样错位、画面发糊：`med21_chest.png` 曾是 `167×167` 而声明 `85×85`（1.965×），已重采样为 `170×170`。
- `uv_rotation` 必须为 `0`。带旋转的模型请在导入前烘焙好（SBM 只读 `uv / uv_size / material_instance`，旋转会被静默忽略 → 手臂 UV 反转就是这类问题）。

## 6. 校验 / 修复工具

```bash
node tools/armor_geo_norm.mjs --check        # 只报告；有问题时退出码 1
node tools/armor_geo_norm.mjs --fix          # 自动改 pivot（备份到 build/armor_geo_backup/）
node tools/armor_geo_norm.mjs --check --all  # 顺带体检 vehicles/entity 等（只查重名、悬空 parent、uv_rotation）
```

Gradle 入口：

```bash
./gradlew armorGeoCheck    # 同上 --check
./gradlew armorGeoFix      # 同上 --fix
./gradlew build            # check → armorGeoCheck 会自动跑，不合规直接失败
```

历史备份：`build/armor_geo_backup/`（全量规范那一轮，12 个文件）、`build/armor_pivot_backup/`（上一轮 8 件胸甲）。

## 7. 新模型接入流程（照做即可）

1. Blockbench 导出 bedrock geometry（`format_version: 1.12.0`）→ 放进 `models/bedrock/armor/`。
2. 贴图按 **2×** 导出到 `textures/armor/`。
3. **先用工具规整**：`node tools/geo_to_armor.mjs --all <源目录> <armor目录>`（枢轴归位 + 额外骨合并 + 版本统一），
   或 `./gradlew armorGeoFix`（只修枢轴，会先备份）。
4. `./gradlew armorGeoCheck` 必须 `0 条问题`。
5. 新建物品类（可抄 `item/armor/Jungle07Chest.java`）→ `ModItems` 注册 → 语言文件加名字 → 加配方；
   整套可用 `node tools/gen_armor_set.mjs` 批量生成。
6. 出物品图标：`python tools/make_armor_icons.py`（离线渲染，按槽位过滤骨骼）。
7. 进游戏 `/give` 验证：站立三视图 + 走动 + 潜行 + 举盾（检查手臂/腿跟随）。F3+T 热重载资源可直接看模型改动。

> 工具清单与所有脚本的用途见 **[tools/README.md](../tools/README.md)**。

## 8. 症状 → 原因对照

| 现象 | 最可能原因 |
|---|---|
| 整件护甲上浮/下沉（胸甲跑到头上） | `armor*` 骨 pivot 与 biped 父骨不一致（典型：`armorBody` 写 22） |
| 左臂护甲横向错位 | `bipedLeftArm` 的 x 写成负数（应为 `+5`） |
| 靴子偏离脚部 | `armorBoot` pivot 写成 `[0,0,0]` / `[0.2,-1,0]`，应为 `[±2,12,0]` |
| 贴图错位 / 发糊 | PNG 与声明不是整数倍，或 `uv_rotation` 未烘焙 |
| 护甲不跟随动作 | 骨骼名拼错（必须精确 `armorBody` 等）或该槽位的可见性没开 |
| 头盔/护腿正常但只有胸甲异常 | 就是 `armorBody` 那一处 pivot |

## 9. `SbmArmorRenderer` 的调试开关

默认关闭，仅在排查时使用：

```
-Ddragonrise.armor.compensate=true    # 按 "bind + 相对原版静息位置的增量" 重设骨骼
-Ddragonrise.armor.yCalib=<单位>      # 配合上一项，正数=向下
```

实测打开补偿会让**所有**护甲下沉 24 单位 —— 说明 SBM 的静息偏移对 y 方向本来就是对的，错位根因在 geo 的 pivot，不要在代码里硬补。

## 10. 从 `.bbmodel` 批量转护甲 geo

```bash
# 1) 转 geo + 贴图（一套模型一份 geo，三槽共用）
node tools/bbmodel_to_armor_geo.mjs --in "D:\Download\xxx兵.bbmodel" ^
     --geo  src/main/resources/assets/dragonrise_reforge/models/bedrock/armor/<name>.geo.json ^
     --png  src/main/resources/assets/dragonrise_reforge/textures/armor/<name>.png ^
     --id   geometry.<name>

# 2) 校验/修 pivot
node tools/armor_geo_norm.mjs --check

# 3) 出正交预览图确认几何/UV（不用进游戏）
python tools/armor_geo_preview.py      # 输出 build/armor_preview/all_armor_preview.png

# 4) 批量生成物品类 / 注册 / 创造栏 / 语言 / 物品模型 / 装配配方
node tools/gen_armor_set.mjs           # 改脚本顶部的 SETS 表即可
```

转换器关键约定（踩过的坑都在这里）：

| 点 | 规则 |
|---|---|
| 贴图选哪张 | bbmodel 常带两张：一张 64px 的副本（`CGA - 副本.png`）+ 一张真实大图。**取被 face 引用最多的那张**，否则贴图全错。 |
| UV 空间 | 用主贴图声明的 `uv_width/height`，并与工程 `resolution`、UV 上界取最大值。**只有引用了“非主贴图”的面才做 UV 换算**；主贴图的面保持原始 UV（否则 `uv_width` 与真实图集尺寸不符时会被整体放大，UV 全错——SAWKM-1 就踩过）。 |
| 贴图尺寸 | PNG 必须是声明尺寸的**整数倍**（本批 5 套都是 2×）。 |
| 立方体旋转 | `free` 格式的 cube 旋转序与 bedrock 不一致，直接导出会把模型压成“平板”。**导出时加 `--strip-rotation`**，还原静止姿势（护甲本来也需要静姿）。 |
| 摆姿势的模型 | 先按**旋转后包围盒中心**分类：先 X 判手臂、再 Y 判头/躯干/腿，避免抬臂被算成头盔。 |
| 一套三槽 | 头盔/胸甲/护腿共用同一份 geo，靠 SBM 的按槽位可见性区分；`SbmArmorRenderer` 缓存键已带槽位，三件同穿不会每帧重建。 |
| 贴图共用 | `gen_armor_set.mjs` 按文件 SHA-256 去重：内容相同的多套模型只引用第一份贴图。 |
| 立方体 | `inflate` 烘进 from/to；`pivot` 保留原 `origin`；面上 `rotation=180` 用负 `uv_size` 表达。 |

### 物品图标（离线渲染，无需 Blockbench）

```bash
python tools/make_armor_icons.py            # 5 套 × 3 槽 = 15 张 512×512，写 textures/item/
python tools/make_armor_icons.py --yaw 315 --fill 0.85 --sets haom,juaw
```

- 复用 1201 工程的 `tools/vehicle_icon_render.py`（Bedrock 离线渲染），按槽位过滤骨骼后再渲，所以每张图标只显示对应部位。
- **必须 `near_smaller=False`**，否则深度判定反了会渲染出背面（看起来像从模型内部往外看）。
- 朝向用 `yaw=315 / pitch=26.565`（front-right 三分之四视角），与工程既有图标风格一致。
